# Glossary

| Term | Plain-language meaning |
|---|---|
| Access token | A short-lived digital pass sent with requests to protected services. |
| Refresh token | A longer-lived secret used to obtain a new access token without signing in again. |
| Token family | The tracked lineage of refresh tokens for one device session. |
| JWT | A signed token containing identity and permission claims. |
| JWKS | A public list of keys services use to verify JWT signatures. |
| MFA | A second proof of identity, such as an authenticator code or passkey. |
| TOTP | A six-digit time-based code generated by an authenticator application. |
| OTP | A short-lived one-time code delivered through a channel such as email or SMS. |
| Passkey / WebAuthn | Password-resistant login using device biometrics or security keys. |
| OIDC | A standard used for identity federation with Google, Apple, or Microsoft. |
| RBAC | Role-based rules deciding which actions a user may perform. |
| Tenant | An organization whose data and permissions are isolated from other organizations. |
| EBC | Entity-Boundary-Control: domain data, external interfaces, and workflow coordination are separated. |
| RLS | PostgreSQL row-level security restricting which tenant records a database session may access. |
| Revocation | Making a previously issued session or token invalid immediately. |
| Device fingerprint | A privacy-reviewed hash of device signals used as one risk input, not as identity proof. |
| K-anonymity | Checking a password hash prefix against breach data without sending the password. |
| Envelope encryption | Encrypting data with a data key that is itself protected by a key-management service. |
| WORM | Write-once-read-many storage that prevents audit records being changed or deleted. |
| Four-eyes principle | A sensitive action requires two distinct authorized staff members. |
| RFC 7807 | A standard JSON structure for API problem responses. |
| CSRF | An attack that tricks a browser into sending an unwanted authenticated request. |
| CORS | Browser rules controlling which websites may call an API. |
| PII | Personal information such as name, email, or phone number. |
| GDPR erasure | A governed process to anonymize personal data while preserving lawful records. |
